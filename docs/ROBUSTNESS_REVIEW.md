# 健壮性修复与验证（2026-09-18）

本轮以全量离线测试及实际代码检查为依据，修复配置生成、跨公司银行分摊与缓存复用问题。此前测试为136通过、21失败、34跳过；修复后174通过、34跳过，3697个参数化子检查通过。跳过项是需显式配置的联网读取测试，本轮没有上传凭证。

## 修复内容

- 月份初始化只在defaults内保存跨账套开关，生成配置能被生产读取器接受；同主体与跨主体均覆盖。
- 新公司基础模板读取注册表，不再默认不存在的weiyu目录。
- 银行总额校验有限值及流水一致性。公司/个人社保、公积金分项保持实际金额，缺项、不平或非法数值阻断；微誉已有各半规则仅限微誉且显式金额优先。
- 银行分析保存金额来源快照，缓存复用与prepare都校验；旧缓存必须重跑llm。
- 收支方向不能证明客户或供应商身份，预加载只接受业务依据与目标目录。
- 明确自用采购不会落入微誉库存商品模板；Linux登录使用的requests纳入运行依赖。

## 验证范围

全量命令：在安装requirements-dev.txt的Python环境运行 `python -m pytest -q`。

`tests/test_linux_month_bank_chain.py` 在临时目录调用项目原有 `.sh` 分发器及初始化脚本，实际生成月份配置、独立工作区，执行PDF拆分、Excel流水匹配和凭证准备。OCR引擎与LLM、动态账套目录为测试替身，未调用真实服务。包含新建公司、跨账套月份、重复初始化保留配置验证。

`tests/test_bank_amount_contract.py` 覆盖公司隔离、非各半分摊、缺金额、NaN/Infinity、流水不一致、金额证据变化及未知企业不能按资金方向创建供应商。

其余更新对齐现行配置和业务约束，未为通过测试放宽借贷、账套或辅助核算校验。历史凭证回放继续通过。

## 使用影响

旧银行分析没有bankSourceAmounts时，需要重新执行llm，再prepare。千云、智轻云公积金/社保分拆缺实际明细时会阻断，不自动补0或猜比例。原先错误生成的月份配置可重新执行同一month命令规范化；会按这次明确传入的目标账套设置跨主体开关。

离线全绿意味着当前覆盖到的逻辑回归通过，不等于真实OCR识别、模型判断、网络恢复和线上记账已完成验收。仍应分阶段复核后上传。
